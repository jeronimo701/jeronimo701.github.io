# Jeronimo701 — проекты и загрузки

Публичный каталог приложений, скриптов и доработок Jeronimo701.

**[Открыть хаб →](https://jeronimo701.github.io/)**

![Обложка каталога](site/assets/social.png)

## Что есть на сайте

- Поиск по названию, описанию и технологиям; клавиша `/` открывает поиск, Escape очищает его.
- Фильтры Windows, Android, Tampermonkey и Nintendo Switch с количеством проектов. Editor показывается и в Windows, и в подборке Switch; пометка указывает, что редактор запускается на ПК.
- Сортировка по рекомендации, названию или свежести релиза.
- Ссылки на последние обычные релизы, исходники и отдельные выпуски для разных ОС. Если есть только предварительная сборка, она явно помечается «Пререлиз».
- Раскрывающиеся списки готовых файлов с размерами; Neon Full и Lite находятся в одной карточке.
- Лента последних выпусков, светлая и тёмная темы, адаптивная вёрстка. По умолчанию включена тёмная тема; ручной выбор запоминается.
- Состояние поиска сохраняется в URL: ссылкой на подборку можно поделиться.

## Автоматическое обновление

GitHub Actions пересобирает и публикует каталог при изменении сайта, вручную через **Actions → Update catalogue and deploy Pages → Run workflow** и раз в 6 часов. [Плановые запуски GitHub могут задерживаться](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule); при отсутствии активности GitHub может отключить расписание публичного репозитория через 60 дней. Проверяйте состояние workflow, если дата на сайте перестала обновляться.

Обновление получает **только публичные репозитории** через `/users/jeronimo701/repos` и их опубликованные обычные релизы. Закрытые проекты и черновики в каталог не попадают. Сам репозиторий сайта из списка исключён. Новые открытые проекты добавляются автоматически; название, категорию, платформы, тематические подборки (`collections`) и порядок можно уточнить в `projects.json`.

Посетители получают готовый `catalog.json` без обращения к API GitHub. Токены в HTML и JavaScript не нужны и не сохраняются. Стандартный `GITHUB_TOKEN` используется только внутри сборки Actions. Если обновление не удалось, сайт сохраняет предыдущую успешно опубликованную версию.

`releases/latest` ведёт к текущему релизу сразу после публикации. Версии на карточках, списки файлов и отдельные ссылки ОС обновляются при следующей сборке каталога. Приложения с debug-подписью и другие ограничения описаны в соответствующих репозиториях.

## Запуск локально

Python 3.10+; дополнительных Python-пакетов и npm-зависимостей нет.

```sh
python scripts/update_catalog.py
python scripts/validate.py
python -m http.server 8080 --directory site
```

Откройте `http://localhost:8080`. Для сборки без авторизации действуют ограничения публичного GitHub API. При необходимости передайте `GITHUB_TOKEN` через окружение, а не через файл или аргумент командной строки.

## Структура

| Файл | Назначение |
|---|---|
| `site/` | Готовый статический сайт, публикуемый в Pages |
| `projects.json` | Авторские названия, категории, платформы, порядок |
| `scripts/update_catalog.py` | Сбор публичных данных и релизов |
| `scripts/validate.py` | Проверка каталога и локальных ресурсов |
| `.github/workflows/pages.yml` | Обновление и публикация через Pages |

В Settings → Pages выбран источник **GitHub Actions**. Workflow не имеет права менять исходники и использует `contents: read`; при публикации также `actions: read` для чтения артефакта, `pages: write` и `id-token: write`.
